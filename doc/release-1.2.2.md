# LyLaunch 1.2.2 · 轻启

**让本地模型走出 LyLaunch：dsh 也能用上它。**

这一版把「外部集成」从插件引擎里彻底拆出来，独立成第二套 Router。拆开的原因很实际——llama.cpp 的 preset 是 Router 启动时读进内存的，共用一个进程就意味着「改外部集成的上下文，必然打断插件正在用的模型」。拆完之后，两边各跑各的，改一个不影响另一个。

## 外部引擎：第二套 Router

- 端口 `18091`、preset `models-ext.ini`、日志 `engine-ext.log`、进程号 `engine-ext.pid`，与插件那套（`18090`）完全分开，**默认关闭**
- 「启用外部引擎」开关：打开时先把插件那套已加载的模型卸载，把显存整块让给 dsh；关闭时收掉外部进程，插件恢复按需加载
- 外部引擎开着期间，插件侧请求加载模型会被**明确拦下**并提示去设置页关掉——而不是悄悄抢显存，最后两边一起 OOM
- 卡片上新增「重启 / 结束」两个按钮，不用再靠命令行或整个程序重启；状态行直接给出 `pid` 和**已加载模型的实际 `n_ctx`**，改完是否真的生效，一眼可见
- 「保持插件引擎运行」开关与它并存，但外部引擎开着时不预热插件那套

## 上下文滑块（只作用于外部引擎）

- 九档：8K / 12K / 16K / 24K / 32K / 48K / 64K / 112K / 122K，默认 16K，松手 400ms 落盘
- 一次改三处，且同源：`models-ext.ini` 的 `ctx-size`、dsh provider 段的 `contextWindow`、以及 dsh 的输出预算（取上下文的 1/4，封顶 8192）
- 插件那套回落各模型出厂值——翻译和 OCR 的请求都很短，跟着调到 64K 只会白吃 KV cache
- 顶档从 64K 提到 **122K**（12K / 16K 之间补了 112K 一档）：按 12GB 卡的实账排的（9B 权重 4.8G、KV 约 35 KiB/token），112K 留余量，122K 是这张卡的天花板
- 真机实测：Router 2.6s 起、首包 12.4s、`n_ctx = 124928` 加载成功；再往上就要挤占桌面显存，会 OOM
- 选到 16K 以下会直接标黄提示「跑 dsh 会爆窗」

## DeepSeek Harness 接入

- provider 段基址从 `18090` 迁到 `18091`；若 dsh 那边还写着旧端口，设置页会直接点出来「点一次接入切到外部引擎」，不用自己比对文件
- 「接入」成功会自动打开「启用外部引擎」并预热，省掉「配置明明对了却连不上」这一段

## 修复

- **滑块调到 64K、引擎仍按 16384 加载**：`start()` 原来是「端口上有应答就复用」，把上次遗留的孤儿 llama-server 当成了自己的。改为按 `engine.pid` 认领；认不出归属的残留先按端口找到 owner 再清掉。实测在 18091 上加载 9B 后 `n_ctx = 65536`，与设置一致
  - 附带修掉：中文 Windows 下解析 `netstat` / `tasklist` 必须按 GBK 解码，否则 `stdout` 为空、判断直接失效
- **dsh 里上下文一直显示 16.4K**：写 provider 段时漏了「按外部档位取值」，拿到的是插件那套的出厂值 16384——引擎按 64K 加载、dsh 却仍按 16K 算预算。已改为同源，并新增自检：已写入的 `contextWindow` 与滑块档位不一致时，设置页标黄提示重接入
- **回答被截断（「已达到输出 token 上限」）**：输出上限原来是 `min(ctx/4, 4096)` 硬顶 4096，现在按窗口大小放到 8192
- **在 dsh 里选 Qwen3-VL-8B 必然失败（`500 model name=qwen3-vl-8b failed to load`）**：全局档位被无差别写进 preset 的每一段，而 VL-8B 的 KV 约 140 KiB/token，112K 光 KV 就要 16GB——12GB 卡在加载阶段就 OOM，报错离真正原因很远（dsh 侧只看到被截断的 500 和五次重试）。现在 `ModelDef` 增加 `ctx_max` 与 `kv_cache`：外部那套按 `min(全局档位, ctx_max)` 截断，写入 dsh 的 `contextWindow` 同源跟着变；VL-8B 封顶 65536 并给 K/V 缓存开 `q8_0`，实测 64K 可加载（5s 出首包），48K 以上不量化仍会 OOM，96K 即使量化也超
  - 这一档的取舍：`q8_0` 只压 KV、不动权重，输出质量基本无感；`q4_0` 同样能跑 64K，但没必要为省这点显存冒退化风险

## 一个可以复现的场景

禁用网卡（真断网）→ 在 dsh 里选云端模型 → 连续重试 5 次全部失败 → 切到「LyLaunch 本地模型」→ 同一个问题 **12 秒答完**，全程零外发。本地 AI 对话插件里用同一个模型，速度一致。

## 升级

直接覆盖安装，配置与模型目录保留。装完之后如果 dsh 那边原来接在 `18090`，进 **设置 → 外部集成** 点一次「接入」，就会切到 `18091` 的外部引擎。
