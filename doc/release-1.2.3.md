# LyLaunch 1.2.3 · 观测

**这一版让引擎「看得见」：谁在跑、跑多快、吃多少显存，都摆在设置页里。**

上一版把外部集成拆成了第二套 Router，但「引擎到底在干什么」只能靠猜——dsh 说连不上时，你得开命令行翻日志才知道 18091 有没有在跑、模型加载到哪个上下文。这一版补上观测：设置里直接看状态、看速度、看历史。同时把桌面净化插件的这一轮改造（毛玻璃、面板重排、图标缓存）一并打包。

## 运行监控：设置 → 外部集成 → 运行监控

不新增导航项，就挂在「外部集成」页里，和「配置」并排。**只有这一页在你眼前时才采样**，切回配置就停——不占端口、不写盘、不打扰正在跑的推理。

- **状态卡**：模型名、上下文占用（`9,537 / 114,688 tok`，带进度条）、输出速度 t/s、提示词 token、缓存命中；下面一行显存 `10,220 / 12,227 MB` + GPU 利用率 + 温度
- **趋势卡**：最近 2 分钟的输出速度与显存曲线。空闲时显示「空闲 · 最近 2 分钟没有解码」，而不是一条贴着底边的直线
- **请求历史**：7 天内累计次数 / 送入 token / 输出 token / 平均 t/s，逐条列出时间、模型、`1,420 → 96 tok`、耗时、t/s。数据只留在本机，超过 7 天自动清
- 顶部可以切「插件引擎（18090）」与「外部引擎（18091）」，同一套 UI 两套数据
- 外部引擎是 dsh 直连，LyLaunch 看不到逐请求明细，所以那一栏只给进程级数据并写明原因——不摆一个永远空着的表

数据来源是引擎自己的接口：Router 的 `/models` 里带着子进程端口，再拿 `/props` 与 `/slots` 的 `n_ctx`、`n_prompt_tokens`、`n_decoded`；速度用两次采样的 `n_decoded` 差分算，不是估算。GPU 走 `nvidia-smi`。全程只读，不加载模型、不改任何配置。

## 桌面净化插件 0.2.14

- **毛玻璃恒开**：去掉那个开关，改成一根「磨砂强度」滑杆（0~100）。**数值越小越不糊、越透**：`≥50` 是系统模糊 + 白雾，`<50` 走清玻璃、只剩一道描边
- **背景实时跟随**：改回 DWM 实时合成，窗口一动、背后一变立刻跟，不再出现「必须拖一下才刷新」
- **主面板重排**：单列、瓦片 78×74 / 图标 32、每行最多 12 个、不限行数全部展示，取消翻页；分类不再靠一页页翻
- **经典白皮肤回单列**，侧边导航点过的项常亮，不再「跳转落不到正位」
- **右上角改齿轮图标**：24×24 幽灵图标，平时无底无边，悬停才浮出淡白胶囊
- **瓦片可拖动换组**，修掉「一拖就变成拖整个窗口」
- **图标磁盘缓存 + 自愈**：打开面板 84/84 都是真图标；库坏了自动重建一次，不会再出现一片白纸
- 插件设置页 49 → **11~17 ms**

## 修复

- **设置页打开慢**：构造 1557 ms → **340 ms**。外部集成页原来在界面线程里同步做两次端口探测，而这台机器对未监听端口要耗满超时；现在丢到后台线程，首帧先显示「正在检测…」
- **显存上限读成 0**：`nvidia-smi` 不在 PATH 里，`vram_total_mb()` 一直返回 0，连带「同时开几个模型」的自动档永远保守取 1。改走绝对路径后正确读到 `12,227 MB`
- **「启用外部引擎」点不动、引擎起不来**：状态探测线程结束后对象已被销毁，开关与启动完成回调再碰它就直接抛异常，后面「加载配置 / 启动引擎」全都没执行。现在引用随线程结束失效，关窗之后才回来的结果只丢不渲染

## 升级

直接覆盖安装，配置、插件与模型目录都保留。装完重启一次程序，运行监控就会出现在 **设置 → 外部集成**（首次进入会新建本地统计库，路径 `%LocalAppData%\LyLaunch\engine_stats.db`）。
